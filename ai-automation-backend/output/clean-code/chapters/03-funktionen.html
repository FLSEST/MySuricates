Kapitel 3

Funktionen

Klein, fokussiert und mit einem klaren Zweck – so sollte jede Funktion sein.

Zusammenfassung

Funktionen sind die ersten Organisationseinheiten in jedem Programm. Sie sind die Verben unserer Programmiersprache, die Klassen sind die Substantive. Die erste Regel für Funktionen: Sie sollten klein sein. Die zweite Regel: Sie sollten noch kleiner sein.

Eine Funktion sollte genau eine Sache tun, diese eine Sache gut tun und nur diese eine Sache tun. Aber wie definiert man „eine Sache“? Eine Funktion tut eine Sache, wenn alle Schritte innerhalb der Funktion eine Abstraktionsebene unter dem Namen der Funktion liegen.

Das Abstraktionsniveau innerhalb einer Funktion sollte einheitlich sein – die sogenannte Stepdown Rule. Wir wollen den Code wie eine Erzählung von oben nach unten lesen können, wobei jede Funktion zur nächsten Abstraktionsebene hinunterführt.

Key Takeaways

1

Funktionen sollten klein sein – maximal 20 Zeilen sind ideal, kürzer ist besser.

2

Eine Funktion, eine Aufgabe (Single Responsibility) – wenn eine Funktion mehr als eine Sache tut, sollte sie aufgeteilt werden.

3

Einheitliches Abstraktionsniveau (Stepdown Rule) – Code sollte wie eine Erzählung von oben nach unten lesbar sein.

4

Wenige Argumente – null ist ideal, dann eins, dann zwei. Drei oder mehr Argumente sollten vermieden werden.

5

Keine Seiteneffekte – eine Funktion soll nur das tun, was ihr Name verspricht, nichts Verstecktes.

6

Command-Query-Separation beachten – eine Funktion sollte entweder etwas tun oder etwas beantworten, nicht beides.
