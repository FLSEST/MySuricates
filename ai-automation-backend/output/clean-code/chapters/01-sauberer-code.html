Kapitel 1

Sauberer Code

Was bedeutet „sauberer Code“ und warum ist er so wichtig für professionelle Softwareentwicklung?

Zusammenfassung

Was bedeutet sauberer Code? Robert C. Martin sammelt Definitionen verschiedener Experten und zeigt, dass es bei sauberem Code nicht nur um Funktionalität geht, sondern um Qualität auf mehreren Ebenen. Bjarne Stroustrup, der Erfinder von C++, betont Eleganz und Effizienz – sauberer Code tut eine Sache gut und verführt nicht dazu, ihn zu verschlechtern.

Grady Booch spricht von Lesbarkeit: Sauberer Code liest sich wie gut geschriebene Prosa. Dave Thomas fordert, dass Code von anderen Entwicklern verstanden und erweitert werden kann – er enthält aussagekräftige Tests und minimale Abhängigkeiten.

Michael Feathers bringt es auf den Punkt: Sauberer Code sieht aus, als wäre er mit Sorgfalt geschrieben worden. Es gibt nichts Offensichtliches, was man noch verbessern könnte. Der Autor des Codes hat sich sichtbar Mühe gegeben.

Key Takeaways

1

Code wird öfter gelesen als geschrieben – daher sollte Lesbarkeit immer Priorität haben.

2

Die Pfadfinder-Regel: Hinterlasse den Code immer besser, als du ihn vorgefunden hast.

3

Sauberer Code ist fokussiert – jede Funktion, Klasse und jedes Modul hat eine klare, einzelne Aufgabe.

4

Softwareentwicklung ist ein Handwerk, das kontinuierliche Übung und Disziplin erfordert.

5

Schlechter Code verlangsamt Teams exponentiell – die anfängliche Geschwindigkeit geht schnell verloren, wenn die Codebasis verrottet.
