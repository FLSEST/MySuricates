Weisheiten und Einsichten aus Clean Code von Robert C. Martin

«Clean code always looks like it was written by someone who cares.»

— Michael Feathers, zitiert in Kapitel 1

«Any fool can write code that a computer can understand. Good programmers write code that humans can understand.»

— Martin Fowler, zitiert in Kapitel 1

«The ratio of time spent reading versus writing is well over 10 to 1. We are constantly reading old code as part of the effort to write new code.»

— Robert C. Martin, Kapitel 1

«The name of a variable, function, or class should answer all the big questions. It should tell you why it exists, what it does, and how it is used.»

— Robert C. Martin, Kapitel 2

«Functions should do one thing. They should do it well. They should do it only.»

— Robert C. Martin, Kapitel 3

«The ideal number of arguments for a function is zero. Next comes one, followed closely by two. Three arguments should be avoided where possible.»

— Robert C. Martin, Kapitel 3

«Don't use a comment when you can use a function or a variable.»

— Robert C. Martin, Kapitel 4

«The proper use of comments is to compensate for our failure to express ourselves in code.»

— Robert C. Martin, Kapitel 4

«Code formatting is about communication, and communication is the professional developer's first order of business.»

— Robert C. Martin, Kapitel 5

«Objects hide their data behind abstractions and expose functions that operate on that data. Data structures expose their data and have no meaningful functions.»

— Robert C. Martin, Kapitel 6

«Error handling is important, but if it obscures logic, it's wrong.»

— Robert C. Martin, Kapitel 7

«If you want clean code, you must first write dirty code, then clean it.»

— Robert C. Martin, Kapitel 1

«Test code is just as important as production code.»

— Robert C. Martin, Kapitel 9

«The first rule of classes is that they should be small. The second rule of classes is that they should be smaller than that.»

— Robert C. Martin, Kapitel 10

«Duplication is the primary enemy of a well-designed system.»

— Robert C. Martin, Kapitel 12
